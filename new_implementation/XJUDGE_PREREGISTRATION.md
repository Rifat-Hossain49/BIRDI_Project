# Pre-registration — Cross-family judge for ConfiBench's scenario masks

Written **before** any judge result was computed. Follows `MISKEY_RESULTS.md`,
which found that population-based confidence cannot separate a wrong checker
from a hard scenario (AUC 0.577) because GPT-4o wrote both the checker and the
RTL population, so they share misreadings.

---

## 1. Hypothesis

A judge population whose errors are **independent of GPT-4o's** — RTLs written
from the same specification by a *different model family* — separates
ConfiBench's over-masked scenarios from its rightly masked ones better than
ConfiBench's own confidence does (AUC **0.614**), and that separation turns into
a published-Eval2 gain when used to decide the masks.

For the separation to exist, the judge must pass the hard (mostly sequential)
corner cases that GPT-4o's own RTLs fail. So judge **accuracy** is expected to
be the binding constraint, and it is measured explicitly.

## 2. Judges — each a separate, fixed test

| id | judge | samples / task | notes |
|---|---|---|---|
| **J0** | existing spec-only pool: Qwen2.5-Coder-7B, Llama-3.1-8B, CodeGemma-7B (all 4-bit) | all usable (~4.7) | already generated; harness validation and weak-judge baseline |
| **J1** | `Qwen/Qwen3.5-27B-GPTQ-Int4`, **zero-shot**, thinking on | 5 | no fine-tuning of any kind |

J1's generation settings are fixed to Qwen's published thinking-mode defaults
before any output is seen. Both judges see the specification and interface only
— the same information ConfiBench's generator had. Golden is never shown to them.

## 3. The rule — identical for every judge, fixed here

For each sub-testbench ConfiBench used in its final evaluation, and each scenario
`s` that ConfiBench masks:

- simulate every judge RTL on that sub-testbench and read the checker's failure
  list;
- `p(s)` = fraction of the judge RTLs that **ran** whose failure list omits `s`
  (i.e. that agree with the checker at `s`);
- if at least **3** judge RTLs ran: **unmask `s` iff `p(s) ≥ 0.5`** (a majority of
  the independent judge agrees with the checker);
- otherwise ConfiBench's decision stands.

The rule never adds a mask. Thresholds 3 and 0.5 are fixed here and will not be
tuned.

## 4. Endpoints

**Diagnostic.** AUC of `p(s)` for over-masked (Golden passes `s`) against
rightly masked (Golden fails `s`), on ConfiBench-4o, beside ConfiBench's 0.614.

**Primary.** Published Eval2 (Eval1-gated, loose 0.8, `m2014_q3` exception) on
**ConfiBench-4o**, per task averaged over its 3 runs, against ConfiBench's
recorded masks, **paired task-level bootstrap** (10,000 resamples, 95% CI).
Scoring reuses `analysis/miskey_eval.py`: start from ConfiBench's recorded result
and apply only the flips the logs prove.

**Held-out.** The same rule on **ConfiBench-4o-mini**.

## 5. Success criterion — per judge

- **Success:** 4o Eval2 CI lower bound **> 0**, **and** 4o-mini point estimate **> 0**.
- Otherwise that judge's result is negative and is reported as such.

## 6. When fine-tuning would be justified — decided now, not after

Fine-tuning a judge is justified **only if** J1 fails §5 **and** the failure is
shown to be one of accuracy rather than of the idea. Operationally: restrict the
diagnostic AUC to tasks where J1's own majority RTL passes the official
testbench. If that restricted AUC is **≥ 0.70**, an accurate independent judge
does separate the classes and a stronger judge is worth building. If it is
**below 0.70**, independence does not help even when the judge is right, and the
cross-family direction stops — no fine-tuning.

Any fine-tuning run must additionally (a) decontaminate its training data against
every VerilogEval / HDLBits problem, by description and by solution, and (b)
exclude training data generated by GPT-family models, which would re-correlate
the judge's errors with GPT-4o's and defeat the hypothesis.

## 7. Scope, stated as a limitation

As in `MISKEY_PREREGISTRATION.md`: only ConfiBench's final masking decision
changes. Its generation, correction loop, testbench selection and multibench
composition are held fixed at what it produced. Judge inference is extra compute
that ConfiBench does not spend, and its cost will be reported.

---

## Amendment 1 — inference engine (made before any J1 output was seen)

**What changed.** J1's engine changes from vLLM with `Qwen/Qwen3.5-27B-GPTQ-Int4` to
llama.cpp with `unsloth/Qwen3.5-27B-GGUF` file `Qwen3.5-27B-Q4_K_M.gguf`.

**What did not change.** Same base model (Qwen3.5-27B, untrained by us), same
prompt, same specification-only input, same 5 samples per task, same sampling
parameters (T 0.6, top_p 0.95, top_k 20, min_p 0), thinking on, same strict
answer extraction, same rule, thresholds, endpoints and success criterion.

**Why.** On Kaggle's 2x T4 (compute capability 7.5), vLLM engine
initialisation failed under all four pre-planned load configurations
(`kaggle_runs/xjudge_j1/j1_generate.log`); no generation was produced, so no J1
output existed when this amendment was written. llama.cpp's CUDA backend
supports this GPU generation. The J1b run also captures vLLM's root cause, so the
reason for the change is documented rather than assumed.

**Known difference.** Q4_K_M and GPTQ-Int4 are different 4-bit quantisations of
the same weights. Both are standard; neither was chosen by looking at results.

**Root cause, captured in the J1b run and corrected here.** The J1b diagnostic
(`kaggle_runs/xjudge_j1b/vllm_diag.log`) shows the failure was
`torch.OutOfMemoryError: CUDA out of memory` inside vLLM's `profile_run`, NOT an
unsupported kernel or architecture. An earlier note in this project guessed at a
compute-capability incompatibility; that guess was wrong. vLLM might well run
this model on 2x T4 with a smaller `max_model_len` or a lower memory-utilisation
target. The engine change therefore remains an operational convenience, and the
reason is recorded accurately rather than as first assumed.

**J0 result, for the record (recorded before this amendment took effect).** J0
FAILED the §5 criterion, as expected for the weak-judge baseline: ΔEval2
−0.0150 on 4o (CI [−0.0363, +0.0064]) and −0.0150 on 4o-mini. Its diagnostic
AUC was 0.661 (4o) and 0.683 (4o-mini), against 0.614 for ConfiBench's own
confidence and 0.577 for same-family item discrimination.
