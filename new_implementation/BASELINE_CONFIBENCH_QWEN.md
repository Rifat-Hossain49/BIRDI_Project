# Equal-model baseline: ConfiBench with Qwen3.5-27B (frozen before running, 2026-09-14)

**Purpose.** The fair-win definition has two parts: our pipeline at <=30B roughly matches
ConfiBench-GPT-4o, AND beats ConfiBench's own method run with the same <=30B model. This
run supplies the second number.

**What is kept from ConfiBench (unchanged code).** Prompts and pychecker pipeline, TBcheck
discriminator `col_70_wrong_row_25_correct`, debug max 3, itermax 10, timeout 40 s,
RTL population of 20 per task, `e_rank_super` (threshold 0.15, K 8), multibench masks
(min_tb 2, min_ratio 0.8), and ConfiBench's own Eval1/Eval2 recorded in each task's data.json.
Settings copied from `config/configs/confibench.yaml`.

**What changes (four patches, `prepare_confibench_qwen.py`).**
1. LLM endpoint: model `qwen3.5-27b` -> local llama-server (Qwen3.5-27B Q4_K_M, same weights as
   our pipeline). Pricing 0.
2. Thinking off. GPT-4o is non-reasoning and ConfiBench's prompts expect direct answers;
   thinking mode would also cost ~5-10x the GPU time (ConfiBench-4o used on average 25.8k
   completion + 68.5k prompt tokens per task; 4.0M + 10.7M per 156-task run).
3. Sampling when ConfiBench passes no temperature: Qwen's recommended non-thinking settings
   (T 0.7, top_p 0.8, top_k 20); explicit temperatures pass through. Max 8192 output tokens
   per call.
4. RTL population generated by Qwen inside ConfiBench (no pre-generated GPT-4o RTLs); iverilog
   from PATH.

**Execution.** All 156 tasks, one run (ConfiBench-4o has 3; we compare against its per-task
average and report that we have one run). Sharded 78/78 by task index over two Kaggle
sessions; inside a session one ConfiBench process per server slot (ConfiBench has no
multithreading), context >= 32k per slot. Resumable: tasks with a data.json are skipped in
later sessions.

**Verified locally before launch.** Patches apply exactly once; bundle excludes the empty
key file check passes; config loads with the frozen values; Qwen dispatch against a mock
OpenAI-compatible server returns stripped answers with thinking off, top_k 20, default
T 0.7 and explicit temperature pass-through, cost 0.

**No tuning.** Whatever ConfiBench-Qwen scores is reported as is.

## Execution Amendment (2026-10-03)

The unresolved 20 tasks use two task workers per kernel, with the same model,
prompts, sampling, parser logic, 30-second parser limit, 20-RTL population,
iteration limits, and scoring. The original parser timeout handler left its
thread running after a timeout; the copied baseline now isolates pure parser
calls in a child process and terminates it at the existing timeout. Returned
values and exceptions are preserved, and a runtime smoke test checks success,
error, large responses, timeout, and child cleanup before task execution.
This infrastructure amendment must be disclosed with the comparison.

Completed task records are published into an atomic archive every minute, with
a separate manifest of unresolved tasks. First audited records are retained;
retries are limited to tasks without a recorded result. A failed result is
retained and is never retried to improve its score. A notebook's COMPLETE
status does not imply all its tasks completed. The frozen canonical checkpoint
and source provenance are in `confibench_finish_20261003/launch_manifest.json`.

### Recovery Amendment: 2026-10-04

The previous archives did not preserve executable within-task resume state.
The October 3 wave returned only two new final records; 18 tasks remain unresolved.
New copied-code instrumentation adds atomic per-call response journals and JSON
iteration state. Replay is scoped and request-checked; incompatible state stops
rather than triggering another stochastic generation. Historical response banks
use exact saved conversations and the first saved candidate population, without
selecting on golden outcomes. Historical token usage is unknown and labelled as
such; replay placeholders are not legitimate historical cost measurements.

The scoring policy, original iteration limit and confidence thresholds are not
reduced to finish the benchmark. Execution amendments and missing/error outcomes
must remain explicit in any reported comparison. The canonical count is task
records, not passes. Two approved CPU-only Kaggle pilots now confirm response
replay after forced interruption and restoration of an actual iteration boundary
on `ece241_2014_q4`. The second pilot skipped nine completed iterations and
replayed four unfinished-prefix responses, with no fresh calls or GPU execution.
It intentionally stopped at the first missing response; no new final task record
was produced. GPU retries remain held pending one capped fresh-generation pilot.
