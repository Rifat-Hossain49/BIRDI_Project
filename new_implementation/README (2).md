# ACTIVE-TB+ — Budgeted Adaptive RTL Testbench Synthesis

ACTIVE-TB+ is the next experimental pipeline built from the completed 156-task ACTIVE-TB run. The previous run showed that Random achieved the best raw hidden-mutant rate (71.54%) while ACTIVE-TB full achieved 70.76% with only 13.14 mean cycles versus 59.47 for Random. The new pipeline therefore targets **equal-budget fault detection and adaptive use of scarce verification resources**, rather than raw kill count at unequal cycle budgets.

## What is new

The new method is `active_adaptive`. It retains the reference-assisted ACTIVE-TB structure but adds a saturation detector and exploration fallback:

```text
Specification + trusted golden RTL
              |
              v
     Verification contract
              |
              v
      Deterministic seed suite
              |
              v
      Visible semantic mutants
              |
              v
        Test x Fault matrix
              |
              v
      Behavioral fault frontier
              |
              v
   BMC + heuristic discrimination
              |
       discriminator found?
        /               \
      yes               no
       |                 |
       v                 v
 evidence-gated      exploration pool
 scenario            coverage + diversity
       |                 |
       |          visible kill found?
       |            /          \
       |          yes          no
       |           |            |
       |           v            v
       |        accept     selective Qwen gate
       |                         |
       |                 useful discriminator?
       |                    /          \
       |                  yes          no
       |                   |            |
       |                   v            v
       |                accept    coverage-only
       |                           exploration
       \____________________  __________/
                            \/
                    update frontier
                            |
                     budget exhausted?
                       /          \
                     no           yes
                     |             |
                     +-------------v
                              freeze suite
                                   |
                         hidden-fault evaluation
```

The exploration score uses only visible mutants, the golden RTL, legal inputs, and a cheap coverage proxy. **Hidden mutants are never used for generation or selection.**

## Coverage proxy

`active_tb/coverage.py` tracks four kinds of inexpensive evidence:

- input value bins and input toggles;
- small Boolean-control combinations;
- statically parseable input-controlled `if`/`case` outcomes;
- golden-output values and output transitions.

This is deliberately called a **coverage proxy**, not simulator statement/branch coverage. It is used to decide which legal exploration scenario is least redundant when mutation discrimination stalls.

## Exact equal-budget experiment

The paper-facing script is:

```bash
python run_budget_sweep.py \
  --output active_tb_plus_budget_full \
  --budgets 8 16 32 64 \
  --methods seed_only random greedy_mutation bmc_only active_no_llm active_full active_adaptive \
  --random-seeds 0 1 2 3 4 \
  --enable-llm \
  --model-path /kaggle/input/models/.../qwen3.5-27b/1 \
  --session-hours 10.5 \
  --stop-before-minutes 30
```

Every budget is a **hard total-cycle limit**. The seed suite itself is strictly fitted to the same budget, so no method is allowed to exceed the stated cycle limit.

Random is repeated with multiple deterministic seeds. The other methods are deterministic under the current settings. The runner converts each logical experiment into checkpoint-safe jobs such as:

```text
b008__random_s00
b008__random_s01
b008__active_adaptive
b016__active_adaptive
...
```

## Checkpoint and resume

The runner checkpoints after every completed `(task, budget, method, random-seed)` job. Portable ZIP snapshots are refreshed periodically and at graceful stop.

The experiment fingerprint prevents mixing incompatible settings. Resume only from a checkpoint generated by the **same budget-sweep experiment**.

An older completed ACTIVE-TB checkpoint can still save time via:

```bash
--reuse-contracts-from /kaggle/input/.../active_tb_full_156_checkpoint_latest.zip
```

Only `contract.json` and `golden.sv` are imported into a shared task cache. Old suites, hidden scores, and completion state are intentionally not imported.

## Kaggle

Use `ACTIVE_TB_PLUS_Budgeted_Adaptive_Kaggle.ipynb` with:

- accelerator: **T4 x2**;
- Kaggle model: **Qwen3.5-27B / Transformers**;
- this project attached as a Kaggle dataset/input;
- optionally the old final ACTIVE-TB checkpoint for contract reuse;
- optionally a previous ACTIVE-TB+ budget-sweep checkpoint for resume.

The notebook retains the isolated-venv workaround used by the successful final run and does not upgrade Kaggle's base NumPy/Pandas stack in place.

## Methods retained for ablation

- `seed_only`
- `random`
- `greedy_mutation`
- `bmc_only`
- `llm_only` (optional in the exact curve because it is expensive)
- `active_no_llm`
- `active_full` (previous ACTIVE-TB)
- `active_adaptive` (new ACTIVE-TB+)

The recommended equal-budget sweep omits `llm_only` by default because four exact LLM-only budgets can require many extra Kaggle sessions. Add it explicitly if the full curve is required.
